# Domain docs

This is a single-context project.

## Read when relevant

- Before exploring the codebase, read the root `GLOSSARY.md`.
- Before changing portfolio scope or behavior, read `docs/portfolio-direction.md`.
- Before changing upward navigation or restoration, read
  `docs/research/upward-navigation.md`.
- Read any ADRs in `docs/adr/` that affect the proposed change.

Skip missing domain documents silently. Create glossary entries and ADRs
through `domain-modeling` when terms or decisions are resolved.

## Consumer rules

Use glossary terms consistently in issues, code discussions, and tests.
If a needed concept is missing, identify the gap for `domain-modeling`.
Surface conflicts with an existing ADR explicitly before revising its decision.
